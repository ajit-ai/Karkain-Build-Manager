## 4. Karkain Build Manager â€” benchmarks: Gradle, Bazel (+ Ninja)

**Positioning and intended users. [VF]** Gradle (by Develocity) is the open-source build system for Java, Android and Kotlin; Bazel is an open-source build/test tool for multi-language, multi-platform and very large codebases; Ninja is a small, speed-focused build system born from Chromium. **[RI]** Gradle suits JVM/Android teams wanting ergonomic DSLs and dependency management; Bazel suits organisations needing hermetic builds; Ninja suits toolchain authors and generated files.

**Major capabilities/modules. [VF]** Gradle: incremental builds/cache/tasks, compiler daemon, parallel execution, dependency resolution/locking/conflict rules, Groovy/Kotlin DSLs, composite builds, Tooling API, Build Scans, Maven/Ivy publishing, JVM/Android/C++/Swift. Bazel: Starlark BUILD files, action graph, caching, parallel/incremental execution, hermetic sandboxing, remote caching/execution (gRPC), query. Ninja: minimal rule/edge graph, fast incremental rebuilds, dyndep, usually generated by CMake/Meson.

**Platform support. [VF]** Gradle runs on JVM platforms (Windows/macOS/Linux). Bazel runs on Linux, macOS and Windows, with community packages for many distros/architectures. Ninja builds on all major platforms.

**Deployment/packaging. [VF]** Gradle wrapper self-provisions the declared version (SHA-256 verification supported); Bazelisk is the recommended installer; Ninja is a small standalone binary with distro packages.

**Architecture & extensibility. [VF]** Gradle: task graph, plugins, init scripts, embeddable Tooling API. Bazel: Starlark rules, toolchains, remote APIs, partners for cache/RBE/UI. Ninja: minimal, extended via generators. **[RI]** Gradle is most programmable, Bazel most rigorous, Ninja most transparent.

**Integration ecosystem. [VF]** Gradle is the official Android build tool, integrating Maven/Ivy repos, IDEs via Tooling API and Develocity. Bazel has language rules and partners for remote cache/RBE/CI/UI. Ninja integrates with CMake/Meson.

**Security/admin. [VF]** Gradle: dependency verification, repository content filtering, distribution checksum verification, Gradle Security Subscription for older versions. Bazel: hermetic sandboxed execution and reproducible builds. Ninja: no comparable built-in supply-chain controls [RI].

**Performance/scalability. [VF]** Bazel documents scale to 100k+ source files and tens of thousands of users, with caching/parallel/remote execution. Gradle documents incremental builds, daemon, caching and parallel execution. Ninja's stated design goal is speed on very large trees (Chromium >30,000 files). **[RI]** Bazel/Ninja generally win on raw incremental latency; Gradle trades some latency for dependency-management breadth.

**Licensing/pricing. [VF]** Gradle, Bazel and Ninja are all Apache License 2.0 (verified from their official repositories). Develocity's commercial acceleration/analytics product has separate pricing: **UNKNOWN â€” not verified**.

**Strengths / weaknesses. [VF+RI]** Gradle: ergonomics/dependency management, but JVM/daemon memory and DSL complexity. Bazel: correctness/hermeticity/scale, but steep learning curve and BUILD upkeep. Ninja: speed/simplicity, but no dependency resolution or high-level language [VF+RI].

**Underserved needs / gaps. [RI]** A build manager co-designed with its language toolchain (no external JVM/Starlark runtime), deterministic diagnostics/exit codes, minimal footprint, and build metadata flowing into project/test tooling.

**Opportunities for Karkain differentiation (PROPOSAL). [RI/PROPOSAL]** Karkain already exposes `workspace list/build/test/check/graph`, `pkg`, `bench`, `prof`, `test --compile` and C-free native targets [VF, PRESENT]. Build **Karkain Build Manager as a CLI/TUI service**: treat `workspace graph` as the dependency graph, record `karkain-diagnostics-v1` codes plus `bench`/`prof` output as artifacts, and use `pkg audit/verify` with `crypto` hashing for supply-chain checks **[PRESENT, unverified â€” probe first]**. GUI is **blocked in v1.2.0**, so offer a TUI and JSON/daemon API, not a dashboard. Differentiate on single-toolchain coherence and zero extra runtime, not on Bazel's remote-execution ecosystem (out of reach without gRPC/TLS [VF gaps]).
